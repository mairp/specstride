# Google Antigravity — Ecosystem research (O1-O4)

All URLs accessed 2026-09-26. Antigravity here means the `agy` CLI
(`google-antigravity/antigravity-cli`), which as of May 2026 is Google's
unified replacement for the old Gemini CLI terminal product, sharing the
Antigravity 2.0 agent harness. This is a materially different (and more
capable) picture than "Antigravity = IDE-only, no headless mode" — Google
shipped a real headless CLI mid-2026.

## Headless/automation status — summary

Antigravity **is** headless-capable in the sense that matters for the questionnaire gate: there is an officially documented, officially supported (per Google staff) non-interactive entrypoint, `agy -p`, with text/JSON/stream-JSON output, a model flag, an effort flag, resumable-or-fresh conversation control, and real exit codes/status enums. This is a strictly stronger position than "IDE-only, interactive-login-only" — the gate condition in the research prompt ("no supported CLI, interactive login only, or IDE-only agent") is **not met**, so per the operator's rule, **Gemini CLI does not get triggered** as a full 4th roadmap.

However "headless-capable" is not the same as "production-ready for a Ralph loop today":
- The permission model for headless mode is broken for the exact case Specstride needs (auto-approved file writes/shell without interactive prompts) — issue #548 says `permissions.allow` is ignored and unapproved tool calls hang forever, silently, past the timeout flag. This is worse than the Codex "UNVERIFIED" precedent Specstride already regrets, because it's a *known open defect* rather than an untested path.
- `--dangerously-skip-permissions` is the closest thing to Claude's `--dangerously-skip-permissions` / an auto-approve-everything mode, but the same issue thread notes it "has its own documented failures" (unspecified in the excerpt reviewed).
- Fixed per-call token overhead (~23-25k tokens) before any real work happens is a real cost concern for a one-pass-per-invocation Ralph architecture that wants small, cheap, frequent passes.
- No support for BYO API key / stable service-account auth as of this date — only cached interactive-login OAuth credentials, reused by the headless invocation. That is workable for a single long-lived machine (login once, then loop), similar in spirit to `claude`'s stored session, but is a weaker isolation story than `prime`'s `--no-session`/`--cwd` pattern or `dsh`'s throwaway `DSH_HOME` overlay — there is no confirmed throwaway-config-home flag for `agy`.
- The whole surface is young and moving fast (CHANGELOG shows ~15 point releases packed into roughly 4 months, with headless-relevant behavior — timeouts, error format — changing between minor versions), so pinning a version and expecting `run_agent()`'s `agy` arm to stay correct for long is optimistic without a version-pin discipline the other backends don't obviously need as urgently.

## Relationship to Gemini CLI

Google announced in May 2026 that it is **sunsetting Gemini CLI for consumer users** and unifying the terminal experience into Antigravity CLI: "Gemini CLI proved the terminal could be an incredible interface for agentic tasks, but your needs shifted." Gemini CLI and the Gemini Code Assist IDE extensions stopped serving Google AI Pro/Ultra/free-tier requests on **2026-06-18**. Antigravity CLI "shares the same agent harness as Antigravity 2.0" (the desktop IDE) and explicitly "took inspiration from core Gemini CLI product and harness components" — so it is a genuine successor sharing the agent core, not a separate product wearing Gemini CLI's old skin. The one carve-out: organizations with **Gemini Code Assist Standard/Enterprise** licenses keep unchanged access to the old Gemini CLI with continued updates — i.e., Gemini CLI survives only on the enterprise-license path, not for individual/Pro/Ultra consumer accounts going forward.

Practical implication for Specstride: since the consumer-facing "headless Google path" *is* now Antigravity CLI (Gemini CLI is being deprecated out from under individual users), researching Antigravity CLI **is** researching the practical Google headless option; a hypothetical dedicated Gemini CLI roadmap would mostly describe a deprecated product for anyone without an enterprise Code Assist license.

## Gemini CLI — pre-research paragraph (for a possible future roadmap)

Gemini CLI (`google-gemini/gemini-cli`, npm `@google/gemini-cli`) is fully open source under **Apache 2.0**, mature (multi-year, high GitHub star count, broad community tooling), and already has a well-documented headless mode: `-p`/`--prompt` for one-shot non-interactive runs, `--output-format json|stream-json` for machine-readable output (the `stream-json` flag shipped via a tracked PR/issue pair, [#10883](https://github.com/google-gemini/gemini-cli/pull/10883) and [#8203](https://github.com/google-gemini/gemini-cli/issues/8203)), and a `--yolo` flag to auto-approve all tool calls non-interactively — a cleaner, longer-lived analogue to Antigravity's `--dangerously-skip-permissions`. Auth is via the `GEMINI_API_KEY` environment variable (a real API key, not just cached OAuth), which is a materially better fit for unattended/CI use than Antigravity's cached-credential-only model. **Given Antigravity clears the headless gate, this paragraph is pre-research only** — per the operator's rule, a dedicated Gemini CLI contract/ecosystem research pass was not launched in this run — but if Antigravity's O4 defects (the permission hang, token overhead, ToS-ban risk) prove blocking in practice, Gemini CLI is the fallback worth a real roadmap, with the caveat that Google is actively deprecating it for non-enterprise accounts as of 2026-06-18.
