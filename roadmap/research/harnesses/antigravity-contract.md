# Google Antigravity: backend-contract research

- **Harness:** Google Antigravity. The headless surface is **Antigravity CLI (`agy`)**, not the desktop IDE.
- **Version inspected live:** `agy` **1.2.11** (linux-x64, released 2026-09-25). Tarball `cli_linux_x64.tar.gz`, sha512 `ca12c262…5081`, verified against the release manifest.
- **Date:** 2026-09-26 (every URL below was accessed on this date)
- **Specstride baseline:** `main` e953aa6
- **Credentials:** there are no Google credentials on this host. Anything that needs a real account or key is marked `documented` or `unknown`.

## Headline

Antigravity is not only an IDE. Google ships a supported, closed-source Go CLI, `agy`. It replaced Gemini CLI, which stopped serving personal and free accounts on 2026-06-18. `agy` has a documented headless "print mode":

- `-p`, `--output-format text|json|stream-json`, `--input-format stream-json` (NDJSON on stdin)
- `--dangerously-skip-permissions`, `--disable-slash-commands`, `--model`, `--print-timeout`
- non-browser auth through `GEMINI_API_KEY` plus `settings.json` `"modelProvider":"gemini"`

Live tests confirmed four things: the API-key path skips OAuth entirely and calls `generativelanguage.googleapis.com` directly; a 200 KiB prompt goes in through stdin NDJSON; the `stream-json` schema is as documented; and the exit codes are as documented. A real model turn could not run without a real key.

## Mapping to the backend contract

- **`run_agent()` arm (proposer.sh:394-499).** A new `antigravity|antigravity:*` arm (spelling: `antigravity[:model]` or `agy[:model]`). It does the following:
  - resolves `SPECSTRIDE_AGY_BIN` (default `agy`);
  - builds a throwaway `HOME` overlay via `mktemp -d` containing `.gemini/antigravity-cli/settings.json` = `{"modelProvider":"gemini"}` (no secret), copies in nothing else, and deletes it afterwards (this is the `dsh` pattern);
  - runs `cd "$WORKDIR"`;
  - pipes the prompt as one NDJSON `user` line on stdin with `--input-format stream-json --output-format stream-json --dangerously-skip-permissions --disable-slash-commands [--model "$MODEL"]`, which avoids ARG_MAX;
  - runs under `run_with_idle_watchdog`.

  A throwaway HOME also loses `PATH`-relative tool config such as git identity, so pass `GIT_*` env vars or copy `.gitconfig`. It needs a pre-flight check that `GEMINI_API_KEY` is set, because otherwise the silent 60 s OAuth wait happens.
- **Stream adapter (run_iteration L1408-1510, lib/agent_stream.py).** Add a new `--provider-format agy-stream-json` and an `AgyAdapter` modelled on `PrimeAdapter`. The mappings are:
  - `init` → `agent_init`
  - `step_update` with `tool_info` → tool call and result
  - `step_update.text_delta` → text
  - `result` → `agent_result`, with usage from `result.usage`
  - `AGY_ERROR` on stderr → error classification

  There is no cost field, so Specstride would compute cost from tokens or leave it null. The existing `--disable-slash-commands` gate at L1430-1441 only applies to claude/bebop. The agy arm must add the flag itself.
- **`critic_call()` (lib/critic.py:2337-2379).** Add a `gemini` provider (not "antigravity", since it is independent of it):
  - `call_openai_chat(prompt, model, timeout, base="https://generativelanguage.googleapis.com/v1beta/openai", key=$GEMINI_API_KEY, "GEMINI_API_KEY")`
  - model from `SPECSTRIDE_GEMINI_CRITIC_MODEL`, defaulting to `gemini-3.8-flash`.

  `antigravity` as a critic name can alias to it.
- **`_critic_context_tokens` (L178-213).** Add a `gemini` branch and a table with 1,048,576 for both current models.
- **Name lists.** Add `antigravity` and `gemini` to `orchestrator.sh:60-64,199`, `proposer.sh:497`, `lib/critic.py:17,2379,2469`, `.env.example` (`GEMINI_API_KEY`, `SPECSTRIDE_AGY_BIN`, `SPECSTRIDE_GEMINI_CRITIC_MODEL`), `README.md`, `wiki/Configuration.md` and `wiki/CLI-Reference.md`. This is best done through the shared registry item.
- **Tests.** Parity for the new adapter goes in `lib/test_telemetry_parity.py`. Add fixture-based `lib/test_agent_stream_agy.py` using the live sample below, and extend `lib/test_critic.py` for `gemini`.

## Risks/unknowns

- **Self-updating binary.** The installer says "automatically self-updates in the background during regular runs", and the updater ran live. I found no documented switch to turn it off, and no pinning. Releases come almost daily, so headless behaviour can change between two Ralph passes. Mitigation to check: a read-only binary path, or network egress blocking to the updater host. Status: unknown.
- **Closed source.** Behaviour can only be checked through the docs and the changelog.
- **The docs and the binary disagree:** allow-rules in headless mode (#1054) and "fail fast" auth. Trust live behaviour over the docs.
- **Silent OAuth wait (~60 s).** This happens with no creds, or when `modelProvider` is not set. Pre-check auth.
- **Skill-overflow class of risk.** The target repo's `AGENTS.md`/`GEMINI.md`/`.agents/` rules (20k-token budget) and built-in skills load. `--disable-slash-commands` only turns off expansion. The large default tool surface (browser, image, web, schedule, subagents) inflates the prompt. It is unknown whether tools can be restricted.
- **Cross-pass memory** through knowledge, brain or summaries in a persistent HOME. Use a throwaway HOME.
- **API-key mode is Gemini-only.** The 1.2.9 note "reduce behavior discrepancies with the non-API-key sign-in path" implies the key path trails account mode.
- **ToS/quota.** Account-mode orchestration is "supported" but draws on personal entitlements. API-key mode is billed on the Gemini API. This is out of scope here and belongs to the ecosystem agent.
- **Watchdog.** Stream-json emits per step, but gaps during long thinking are unknown.
- **No cost in the stream**, and no max-turns flag.

## What the vendor would have to ship for this to become integrable, and how to detect it

This harness is **already integrable** for the proposer. The following would remove the remaining caveats, each with a way to detect it:

1. **An auto-update opt-out or version pin.** Detect: `agy --help`, or the docs for a `--no-update`/`autoUpdate` setting, or an env var in `strings`. Watch the CHANGELOG for "auto-update".
2. **A flag to disable rules/AGENTS.md and to restrict tools**, for example `--no-rules` or `--allowed-tools`. Detect in `--help` and on the docs/rules page.
3. **Headless auth fail-fast honoured with no tty.** Detect: re-run inv2; it should exit non-zero in under 5 s.
4. **Allow-rules honoured in headless mode** (issue #1054 closed). This would allow scoped permissions instead of `--dangerously-skip-permissions`.
5. **A cost field in `result`.** Detect by grepping the CHANGELOG for "cost".

## Verdicts

- **Proposer: go-with-caveats.** Spelling: `antigravity[:model]`. Invocation: a throwaway HOME, `modelProvider: gemini`, `GEMINI_API_KEY`, NDJSON on stdin and stream-json. It needs a new `AgyAdapter`. The first roadmap item should be a spike with a real key: "reply OK", then "create hello.txt", then a stream-json tool sample.
- **Critic: go, through direct Gemini HTTP** (`gemini` provider, OpenAI-compatible endpoint, `gemini-3.8-flash`, 1,048,576 tokens). **Not through agy.**
- **Gemini CLI gate:** Antigravity can run headless, so Gemini CLI does not need to enter. It is also officially being phased out: Google announced at I/O on 2026-05-19 that it would stop serving personal and free tiers on 2026-06-18 (https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/).
