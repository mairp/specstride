# OpenCode: backend contract research

- **Harness:** OpenCode (the open-source terminal coding agent. The repo moved from `sst/opencode` to `anomalyco/opencode`, which `gh api repos/sst/opencode` now redirects to. MIT licence.)
- **Version tested:** `opencode-ai@1.18.32` from npm (tag `v1.18.32` = commit `545f51d26cc39a907d2867492d498d9607ea5fa4`)
- **Date:** 2026-09-26
- **Source refs:** `oc@545f51d:<path>` means `anomalyco/opencode` at commit 545f51d. Line numbers are from the raw file at that commit.
- **Specstride refs:** `main` e953aa6 (`proposer.sh`, `lib/critic.py`, `lib/agent_stream.py`, `lib/prime_stream.py`)
- **Live model used:** `gw/gemini-2.5-flash-lite`. `gw` is a custom OpenAI-compatible provider pointed at the local gateway `http://localhost:4000/v1`. It was defined only through the `OPENCODE_CONFIG_CONTENT` env var, and the key was referenced as `{env:LITELLM_API_KEY}`, so no key was written to disk. The host's `OPENAI_API_KEY` is rejected by api.openai.com (401 "Incorrect API key"), so the "OpenAI mini model" route was not usable. `LITELLM_API_KEY` from the environment worked against the gateway.

## Mapping to the backend contract

**1. `proposer.sh` `run_agent()` (L394-499): a new `opencode|opencode:*` arm**
- Spelling: `opencode[:provider/model]`. Reject `--model` together with a suffix, like the `dsh` arm does (L406-409).
- Binary: `${SPECSTRIDE_OPENCODE_BIN:-opencode}`, with the `command -v` check and rc 127 as in the other arms.
- Prompt: write it to a temp file and pass `SPECSTRIDE_STDIN_FILE` (as the `claude` arm does, L438-445). Never pass argv (E2BIG was proven at 200 KiB). Stdin must always be a closed file, because `run` blocks reading a non-TTY stdin.
- Args: `run --format json|default --title "specstride-$ROLE-iter-$iter" -m "$provider/$model" --dir "$WORKDIR"`. `--title` **suppresses the extra title-generation LLM call**. Without it, OpenCode re-sends the first user message (the whole 200 KiB phase prompt) to the small model just to name the session; the session title "BIG-OK 545" in the live test proves that call happened.
- Permissions: **omit `--auto`**. Pass `OPENCODE_PERMISSION='{"external_directory":"deny","doom_loop":"deny","skill":"deny"}'`, overridable by `SPECSTRIDE_OPENCODE_PERMISSION`. Edits and bash stay at the default allow. Asks never hang (they are auto-rejected), but they surface as a silent tool failure, so log them.
- Isolation, following the `dsh` overlay pattern: `mktemp -d` an overlay and export `XDG_CONFIG_HOME/XDG_DATA_HOME/XDG_CACHE_HOME/XDG_STATE_HOME` and `TMPDIR` into it. Keep `HOME` real if the operator's `~/.claude/CLAUDE.md` should be excluded via `OPENCODE_DISABLE_CLAUDE_CODE=1` instead. Pass config via `OPENCODE_CONFIG_CONTENT` (`autoupdate:false, share:"disabled", snapshot:false` optional, custom providers with `{env:VAR}` keys). Export `OPENCODE_DISABLE_AUTOUPDATE=1`, `OPENCODE_DISABLE_CLAUDE_CODE=1` and `OPENCODE_DISABLE_EXTERNAL_SKILLS=1`. `rm -rf` the overlay afterwards. Consider one overlay per attempt rather than per pass, to keep the models.dev cache and provider npm installs warm (the first run downloads `@ai-sdk/openai-compatible` into cache) and to avoid a network fetch per pass (`OPENCODE_DISABLE_MODELS_FETCH` plus `OPENCODE_MODELS_PATH` can pin the catalog).
- Auth: if `auth.json` is needed (OAuth providers), copy it into the overlay's data dir. Env-key providers need nothing.
- Watchdog: wraps normally. Idle risk: there is no stdout during long tools or long generations (events fire on completion only), so `IDLE_TIMEOUT` must tolerate that or rely on the CPU/disk liveness signals. Known upstream hangs (#35870, #47709, #44782, #44901 "step_finish but never exits") mean the watchdog **will** fire sometimes. The stream adapter can shorten #44901: once it sees `step_finish.reason=="stop"` it knows the pass is done, and a missing exit can be classified as a harness hang rather than an agent stall.

**2. `run_iteration()` (L1408-1510)**
- The `shared` array (L1423-1441) is claude/bebop-only; OpenCode needs none of `--dangerously-skip-permissions`, `--verbose` or `--disable-slash-commands`. The skill equivalent is `permission.skill=deny` plus the `OPENCODE_DISABLE_*` env vars, with the escape hatch `SPECSTRIDE_PROPOSER_SKILLS=1` mirroring L1437.
- With `AGENT_STREAM=true`: add `--format json` and pipe through `agent_stream.py --provider-format opencode-json`, with metadata.json written like the Prime branch (L1466-1495) using `"provider_format": "opencode-json"`.

**3. Stream adapter: `lib/opencode_stream.py` (`OpenCodeAdapter`) next to `PrimeAdapter`, registered in `select_provider_adapter` and `observability_start` (`agent_stream.py` L262-294)**
- A new adapter is needed, because the schema is neither claude-stream-json nor prime-v3. See the mapping below.
- `agent_init` must be synthesized, since OpenCode emits no init record. Do it from the first record's `sessionID` plus the model that Specstride passed with `-m`.
- `finish()` must synthesize `missing_terminal` when no `step_finish(reason=stop)` and no `error` record arrived (the same pattern as `ClaudeAdapter.finish`, L242-259).
- Tool names are lowercase (`write`, `edit`, `bash`, `read`, `apply_patch`, …) and the path key is `filePath`. `looks_like_evidence` (L110-131) only accepts `Write/Edit/MultiEdit/NotebookEdit/Bash` and `tool_target` knows `file_path`/`command`, so the adapter must normalise names (`write`→`Write`, `edit`→`Edit`, `bash`→`Bash`, `apply_patch`→`Edit`) and add `filePath` to `TARGET_KEYS`/`extract_target_paths`. Otherwise evidence detection silently never fires.
- Test pins: `lib/test_agent_stream*.py` (a fixture from the sample below) and `lib/test_telemetry_parity.py` (backend parity).

**4. `lib/critic.py`**
- `critic_call()` (L2337-2379): add `opencode` / `opencode:<provider>/<model>`. ### Proposed mapping onto the `agent_stream` vocabulary

| OpenCode record | Specstride event | Fields |
|---|---|---|
| first record (any type) | `agent_init` (synthesized) | `model` = the `-m` value Specstride passed (not in the stream); `tools` = unknown (omit or 0); `session_id` = `sessionID` |
| `step_start` | none (turn boundary); count turns | `num_turns += 1` |
| `text` | `agent_text` | `text` = `part.text` (sanitised via policy, as in `ClaudeAdapter._consume_block`) |
| `reasoning` (only with `--thinking`) | ignored (or debug-only) | none |
| `tool_use` with `state.status=="completed"` | `agent_tool` (+ `evidence_writing` on the first match) | `tool` = normalised name (`write`→Write, `edit`→Edit, `bash`→Bash, `read`→Read, `apply_patch`→Edit, others TitleCase); `tool_id` = `callID`; `target` from `state.input.filePath`/`command`/`pattern`; tool output is **not** forwarded |
| `tool_use` with `state.status=="error"` | `agent_tool` with `status:"error"` plus a diagnostic | `error` = `state.error` |
| `step_finish` | usage accumulation; terminal when `reason=="stop"` | sum `tokens.input/output/reasoning`, `cache.read` → `cache_read_tokens`, `cache.write` → `cache_creation_tokens`, sum `cost` → `cost_usd` (0 for custom providers without a `cost` config; real USD for models.dev providers); `stop_reason` = `reason` |
| `error` | terminal `agent_result` status=error | `reason_code` = `provider_error` (`APIError`, keeping `statusCode`/`isRetryable`) or `harness_error` (`UnknownError`); `reason` = `error.data.message` |
| EOF with no `step_finish(stop)` and no `error` | `missing_terminal` (synthesized in `finish()`) | as in `ClaudeAdapter.finish` |
| EOF after `step_finish(stop)` | `agent_result` status=success | `duration_ms` = last timestamp − first timestamp; `num_turns`; token totals; `cost_usd` |
| `step_finish(stop)` with the process still alive after N s | diagnostic `terminal_without_exit` (#44901) | lets the watchdog classify a harness hang |

## Risks/unknowns

1. **Upstream headless hangs (high).** Open issues report `opencode run` hanging at startup or bootstrap (#35870, #47709, #46142, #44782), hanging on quota exhaustion instead of erroring (#40747), and emitting the terminal `step_finish` but never exiting (#44901). None occurred in 6 runs here, but the watchdog will be the backstop. The adapter should emit a `terminal_without_exit` diagnostic so these are not misdiagnosed as agent stalls.
2. **Sparse stdout (medium).** Records are emitted only on part completion. A 20-minute `bash` tool, or a long single generation, produces no stdout. The idle timeout and watchdog liveness must account for this.
3. **No model in the stream, and cost is 0 for custom providers (low).** `agent_init.model` must come from Specstride's own argument. Cost is real only for models.dev-catalogued providers or when `cost` is configured.
4. **`--auto` scope (medium).** It approves `external_directory`, i.e. writes outside the workdir. The arm must not use it; use deny rules instead. There is no OS sandbox, and bash is unconfined.
5. **Auto-reject can yield rc=0 with empty output (#36413).** The adapter should treat "no text and no successful tools" as suspicious.
6. **Exit code 1 is overloaded (low).** Argument errors, provider errors and harness errors are all rc=1; tell them apart via the JSON `error.name`. Max-steps exhaustion is rc=0. Signal exits and max-steps were not tested live.
7. **Title generation doubles input cost** for large prompts unless `--title` is passed (verified).
8. **Postinstall writes to the real `$HOME`/XDG and `/tmp`**, and the first run writes `opencode.jsonc` and `.gitignore` into the config dir. Install and run with the overlay env; `TMPDIR` must be included.
9. **Release churn (medium).** v1.18.x shipped with `v2` runner refactors in flight (#50062 mentions "`opencode run` (v2)"). Flags like `--auto` are recent (hidden aliases `--yolo`/`--dangerously-skip-permissions`). Pin the version and re-run the fixture test on bumps.
10. **Project `AGENTS.md`/`opencode.json` in the target workdir** load by default. Disabling them (`OPENCODE_DISABLE_PROJECT_CONFIG=1`) also drops the project's own agent instructions; this is an operator choice.
11. **Not verified:** OAuth-only providers in an overlay (copying `auth.json`); SIGTERM exit codes; the `steps` cap behaviour; concurrent passes sharing one overlay (SQLite locking); a real OpenAI-key run (no valid key on the host).

## Verdicts

- **Proposer: go-with-caveats.** A documented headless `run`, stdin prompts (200 KiB verified), no-hang permission handling, a clean XDG+TMPDIR overlay and a JSONL stream all work live. The caveats are the upstream run-hang bugs, completion-only stdout (watchdog tuning), a new stream adapter with tool-name normalisation, and passing `--title`/deny rules to avoid cost and scope traps.
- **Critic: go-with-caveats.** Use direct HTTP (`call_openai_chat`/`call_claude`) against the provider/model named in `opencode:<provider>/<model>`. OpenCode itself has no model API. A deny-all `--agent` CLI path is verified tool-less at config level but has not been run live, so keep it only as a fallback for OAuth-only credentials.
