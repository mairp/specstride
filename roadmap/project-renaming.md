# Project renaming: naming shortlist and launch positioning

Date: 2026-09-09

Status: **Planned** — naming exploration; no replacement name has been selected.

## Objective

Explore a more marketable name for Wiggum that improves attraction, visibility,
and adoption while reflecting the project's purpose: turn specifications into
working code, with review and verification at every phase.

The recommendations below are branding judgments, not measured adoption
predictions.

## Naming shortlist

| Name | Why it could work | Possible tagline | Main tradeoff |
|---|---|---|---|
| **Specstride** | Communicates purposeful progress from a specification. Strong fit for the existing project. | From specs to tested code. | “Spec” appeals mainly to technical users. |
| **Loopstead** | Suggests steady, persistent execution. Friendly enough for an open-source community, with room to grow. | Keep building. Check every step. | Needs a subtitle to explain its purpose. |
| **Proofstride** | Makes evidence and verification central to the brand. | Every step backed by evidence. | “Proof” can suggest formal mathematical verification. |
| **Phasewright** | Reflects building software carefully, phase by phase. Has a craftsmanship feel. | Build by spec. Verify by phase. | People may hear “phase right” when spoken. |
| **Iterail** | Combines iteration with rails: repeated execution with structure. Compact as a CLI command. | Autonomous coding, on track. | Pronunciation and spelling are less obvious. |

## Recommendation

**Specstride** is the strongest candidate for immediate clarity. It connects
specifications with forward progress, sounds professional, and fits what the
project does. **Loopstead** is the alternative for personality and a broader
long-term brand.

Specstride reads naturally in prospective commands:

```bash
specstride run
specstride status
specstride resume
```

These are naming examples, not currently implemented commands.

## Possible launch presentation

> **Specstride**
>
> From specs to tested code.
>
> An autonomous coding orchestrator that drives your agent through implementation,
> critic review, and verification—phase by phase.

## Visibility and adoption suggestions

- Keep “Ralph loop” in the README description and repository topics so people
  searching for the technique can still discover the project.
- Use “formerly Wiggum” during the transition and preserve the old command as an
  alias.
- Lead the README with a short demonstration showing a failed check, an automatic
  correction, and an approved phase.

## Preliminary naming overlap screen

The initial web search found closely related software uses for these candidates,
so they were excluded:

- [Prooflane](https://prooflane.ai/) — AI assurance and release decisions.
- [Loopwright](https://github.com/dtkmn/loopwright) — evidence and verification for
  AI agent loops.
- [Runward](https://github.com/stranxik/runward) — a delivery framework for agentic
  systems.

The shortlist still needs domain, package-name, and trademark availability checks
before committing. This initial screen does not establish availability.
